# 三场景与中文连续操作验收

## Purpose

保留原始 requirements.txt 第 33–38 章的完整操作验收意图，以通用合成输入描述场景，不复制或改写原有项目、姓名、任务正文和示例文件。场景承接 F001–F008 的已有内核规则，原始数据保持原位；本次迁移不表示重新运行这些验收。

## Requirements

### Requirement: R033 会议连续操作

系统 SHALL 用现行查询、选择、节点修改、角色属性和撤销工具完成原始会议十个连续操作场景，并保持明确的文档目标与节点指代。

#### Scenario: R033-S01 获取会议结构

- **WHEN** 用户要求查看当前会议文档结构
- **THEN** 返回 get_outline 的真实大纲，不凭已有对话重新编造文档树。

#### Scenario: R033-S02 选择议题

- **WHEN** 用户按标题指定一个现有议题
- **THEN** 先查找节点再选择；唯一命中设置 Selected Node，多候选返回候选等待明确，不随机选中。

#### Scenario: R033-S03 添加讨论

- **WHEN** 用户要求在当前议题下新增一条讨论并给出内容
- **THEN** 在该议题下创建 Discussion 节点，保留用户内容并更新最近新增指针。

#### Scenario: R033-S04 将刚加的讨论改为结论

- **WHEN** 用户紧接着要求把刚才这条改成结论
- **THEN** 解析最近新增节点，将 Discussion 改为 Conclusion，保持节点 id 与正文。

#### Scenario: R033-S05 将结论改回讨论

- **WHEN** 用户纠正刚才的角色变更并要求改回讨论
- **THEN** 修改同一节点为 Discussion，不新增重复节点或改变其他议题。

#### Scenario: R033-S06 添加会议决定

- **WHEN** 用户明确新增一个会议决定
- **THEN** 在目标上下文创建合法的 Decision 节点并保留请求内容。

#### Scenario: R033-S07 添加待办和属性

- **WHEN** 用户在一句话中提出待办正文、负责人和截止时间
- **THEN** 创建 Action Item，依据当前 Profile 设置合法的负责人和截止属性；未明确的值不能捏造。

#### Scenario: R033-S08 改待办负责人

- **WHEN** 用户指代刚才新增的待办并给出新的负责人
- **THEN** 定位同一待办，修改负责人属性，保持其他属性与内容。

#### Scenario: R033-S09 移动会议内容

- **WHEN** 用户指定一个内容节点及其新的讨论父节点
- **THEN** 明确定位后移动，保持节点 id、正文和属性，拒绝非法父子关系或循环。

#### Scenario: R033-S10 撤销会议移动

- **WHEN** 用户要求撤销上一条成功的移动
- **THEN** 恢复移动前的内容与顺序，按 F004 保持 revision 与已发 id 单调，不将 sidecar 独立失败误报为正文未保存。

### Requirement: R034 项目连续操作

系统 SHALL 使用现行 project Profile 与内核工具完成原始项目十个场景；测试中的数值 progress 只适用于明确定义该属性的合成任务，不能据此改写用户项目的叙述性进展或恢复已移除的日期字段。

#### Scenario: R034-S01 选择项目阶段

- **WHEN** 用户指定一个现有阶段
- **THEN** 查询并选中该节点；同名时先明确章节或候选。

#### Scenario: R034-S02 连续创建三个任务

- **WHEN** 用户要求在选定阶段下增加三个明确任务
- **THEN** 按请求顺序创建三个合法 Task，并正确更新最近新增与选中状态。

#### Scenario: R034-S03 设置任务负责人

- **WHEN** 用户用任务标题指定负责人修改
- **THEN** 定位对应 Task，仅修改其负责人属性；歧义反馈候选。

#### Scenario: R034-S04 修改任务状态与数值进度

- **WHEN** 合成任务的 Profile 支持 progress，用户明确要求状态为进行中、数值进度为 50
- **THEN** 更新合法的状态与 progress=50；不能把普通进展描述转换成整数，也不能写入不支持该属性的角色。

#### Scenario: R034-S05 添加项目风险

- **WHEN** 用户明确在风险章节增加一个风险
- **THEN** 创建合法 Risk 并放入指定风险父节点，正文保持请求语义。

#### Scenario: R034-S06 调整任务阶段

- **WHEN** 用户明确要求将任务从一个阶段移到另一阶段
- **THEN** 改变其父节点，保留任务 id、正文和属性；不根据临时打开文件更换文档。

#### Scenario: R034-S07 将任务排到第一位

- **WHEN** 用户要求某阶段内的任务排在第一项
- **THEN** 只重排该父节点的有序 children，保持其他节点及内容。

#### Scenario: R034-S08 修改项目目标文字

- **WHEN** 用户提供项目目标的新标题或内容
- **THEN** 只更新相应文字，Node ID 保持不变。

#### Scenario: R034-S09 删除任务

- **WHEN** 用户明确指向某任务并要求删除
- **THEN** 删除对应节点并清理指向已删节点的状态引用，不误删同名节点。

#### Scenario: R034-S10 撤销删除

- **WHEN** 用户紧接着撤销任务删除
- **THEN** 恢复任务内容、属性和树中位置；后续新增不复用已发 id，revision 不回退。

### Requirement: R035 思路连续操作

系统 SHALL 保留思路整理八个场景的角色转换、结构编辑与中文指代行为；新增章节和移动可由多个明确工具完成，使用现行批量工具时遵守一次事务与撤销边界。

#### Scenario: R035-S01 添加想法

- **WHEN** 用户要求在指定方向下新增想法
- **THEN** 新增 Idea 节点并保留用户内容。

#### Scenario: R035-S02 想法改为方案

- **WHEN** 用户要求刚才这条改成方案
- **THEN** 将同一节点的角色从 Idea 改为 Solution，保持 id、内容和合法属性。

#### Scenario: R035-S03 添加疑问

- **WHEN** 用户要求新增一个待思考的问题
- **THEN** 在指定位置创建 Question 节点。

#### Scenario: R035-S04 创建章节并移动疑问

- **WHEN** 用户要求建立独立待讨论章节并把已有疑问移入
- **THEN** 创建目标章节并移动原 Question，不复制成第二条疑问；目标或引用不明确先查询。

#### Scenario: R035-S05 同时增加问题与方案

- **WHEN** 用户在一次请求中明确给出问题和对应方案
- **THEN** 分别创建合法的 Problem 与 Solution，并按已明确的父子或同级关系放置；不确定的关系先澄清。

#### Scenario: R035-S06 改标题

- **WHEN** 用户要求修改选定思路节点标题
- **THEN** 更新标题并保留节点 id、正文和其他结构。

#### Scenario: R035-S07 调整结构

- **WHEN** 用户明确要求交换同一父节点下两条思路的顺序
- **THEN** 通过 reorder_node 调整顺序，节点 id 与内容保持；其他移动仍由对应内核工具校验，拒绝环形、非法角色或属性，不直接编辑底层 JSON 或 Markdown。

#### Scenario: R035-S08 连续指代修改

- **WHEN** 用户先增加一个想法，接着说“这个改成方案”，再给出新的标题
- **THEN** 三句话持续作用于同一个 Last Created Node，完成创建、Idea 转 Solution 和标题更新；其他指代结合 selected、lastEdited、lastCreated 与真实文档解析，缺少上下文或存在多候选时不能猜测。

### Requirement: R036-R038 多轮、歧义和真实体验

系统 SHALL 区分可复现的内核操作、中文 Skill 映射和真实宿主体验；自动化用例存在不代表已经完成本轮真实界面验证。

#### Scenario: R036-S01 连续操作保持目标

- **WHEN** 用户先选择节点，再新增、修改属性、移动并撤销
- **THEN** 每次引用对应真实节点，成功保存及版本按当前策略推进，删除或撤销后不保留指向不存在节点的无效指针。

#### Scenario: R037-S01 多个同名候选

- **WHEN** 查找得到多个同名节点或未找到明确目标
- **THEN** 返回候选或具体错误，不随机操作，不产生半完成修改。

#### Scenario: R038-S01 分层验收

- **WHEN** 验证三场景和连续中文交互
- **THEN** 分别记录内核工具用例、Skill 加载、外部文件集成和真实宿主体验结果；未执行项保持未验证，不修改用户项目文件作为测试。

#### Scenario: R038-S02 三份真实规模文档体验

- **WHEN** 正式发布前执行原始需求的人工体验验收
- **THEN** 使用一份会议、一份项目、一份思路整理的真实规模副本或合成文档，每份完成至少十次连续自然语言操作，覆盖新增、修改、删除、移动、排序、改角色、改属性及撤销；检查用户无需知道 Tool、Node ID 或 IR 即可完成操作，原个人项目文件保持不变。
