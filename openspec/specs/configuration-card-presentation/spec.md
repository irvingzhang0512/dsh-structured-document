# F011 设置卡外观对齐宿主卡片

## Purpose

为 dsh-structured-document 的设置卡外观对齐宿主卡片维护唯一可编辑的行为与验收规格，保留原编号 F011，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F011 设置卡外观对齐宿主卡片

系统 SHALL 按下列场景保留已确认的配置卡产品外观和交互预期；旧卡片的源码与历史验证保持，当前 Desktop 新配置桥及实际可达性仍须按 F013 change 验收。本次只迁移文档，没有重新执行产品验收。

#### Scenario: F011-S01 场景与预期

- **WHEN** 用户展开、收起或操作配置卡
- **THEN** 场景与预期：F010 的设置卡不再自绘"扁平、常展开的盒子"，改为按宿主 `PluginCard` 的布局画出**可折叠卡片**：头部（`<button>`）显示插件名 + 版本号 + 一句副标题，右侧放覆盖状态（"用户覆盖"／"继承组装层"）与 chevron（展开时旋转 180°）；主体是**带分隔线的设置行**，每行左侧为标签与说明（标签 13px/20、说明 12px/18 次级色）、**控件行内右对齐**——`默认场景模板` 行右侧为下拉、`自动保存` 行右侧为开关、`撤销栈深度` 行右侧为数字输入；保存与放弃按钮移到卡片右下角操作行。样式一律使用 `--dsw-alias-*` 主题令牌并给兜底值。**卡片 chrome 的数值以宿主 `PluginCard` 的真实规则为准**（本插件卡片与宿主内置卡片同页并列，对比基准是宿主）：`.5px solid --dsw-alias-border-l4` + `background:bg-layer-3` + `border-radius:16px`，展开态 `background:bg-layer-2` + `border-color:label-dimmed`；主体／设置行／操作行的分隔线同为 `.5px --dsw-alias-border-l2`。其余布局（头部、行、操作行、分段控件、输入框）照 开发 Skill 的卡片外观配方 §8。

#### Scenario: F011-S02 边界与异常

- **WHEN** 用户展开、收起或操作配置卡
- **THEN** 外观变化不改变 F010 的配置语义：草稿与显式保存、revision 冲突保护、清除覆盖回退组装层、`currentFile` 不进表单、配置服务软依赖均保持。不得导入宿主服务端或不公开的客户端实现值，遵守客户端纯度边界。卡片收起只隐藏主体、组件保持挂载，未保存草稿不因收起丢失；窄宽度下标签列与控件不得重叠或溢出。

#### Scenario: F011-S03 验收条件

- **WHEN** 用户展开、收起或操作配置卡
- **THEN** 验收条件：与宿主自带卡片、插件市场卡片并排时视觉语法一致（可折叠头部、行间分隔线、控件右对齐、操作按钮在右下角）；头部显示插件名、版本号与副标题；覆盖状态随"字段是否出现在用户层"变化；三行的控件类型与 F010 字段一致（下拉／开关／数字，且数字最小 1）；保存与放弃行为与 F010 相同；键盘可达（头部按钮可聚焦、`aria-expanded` 与主体 `id` 正确关联）。

#### Scenario: F011-S04 **版本号的取得方式（本次取舍）**

- **WHEN** 用户展开、收起或操作配置卡
- **THEN** 版本号不硬编码，由构建期从 `package.json` 的当前 `version` 读取并 `define` 注入（`__DSD_VERSION__`），浏览器 bundle 只有相应字符串字面量；运行时不读文件、不引入 Node 内建。源码声明 `declare const __DSD_VERSION__: string | undefined`，未打包直接运行时回退 `'0.0.0-dev'`，只影响显示。验证源码无与包版本绑定的硬编码，构建显示值与当前包一致；旧 0.2.0 产物值只是原验证记录，不是当前期望版本。
