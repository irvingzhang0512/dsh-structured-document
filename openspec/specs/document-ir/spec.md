# F001 统一文档 IR 与 Profile

## Purpose

为 dsh-structured-document 的统一文档 IR 与 Profile维护唯一可编辑的行为与验收规格，保留原编号 F001，区分当前预期、尚未实现设计和历史验证；原始需求、项目资料及旧文档继续原位只读保留。

## Requirements

### Requirement: F001 统一文档 IR 与 Profile

系统 SHALL 按下列完整场景落实统一文档 IR 与 Profile的预期、边界与验收。本节迁入已有功能规则；本次仅迁移文档，没有重新执行产品验收。

#### Scenario: F001-S01 场景与预期

- **WHEN** 用户载入或保存会议、项目、思路文档
- **THEN** 场景与预期：会议、项目、思路整理等文档使用同一节点树 IR：稳定 id、标题、正文、角色、属性与有序子节点；Profile 约束角色与属性。

#### Scenario: F001-S02 边界与异常

- **WHEN** 用户载入或保存会议、项目、思路文档
- **THEN** 边界与异常：根节点及父子关系受校验；属性类型／枚举按 Profile，不能绕过模型写非法状态；插件不拥有文件树。

#### Scenario: F001-S03 验收条件

- **WHEN** 用户载入或保存会议、项目、思路文档
- **THEN** 验收条件：各 Profile 的有效文档可读；非法角色／属性拒绝；保存重载保持节点 id。
